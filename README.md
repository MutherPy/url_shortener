# URL shortener

## Запуск у Docker

Виконуй команди з каталогу `url_shortener`.

Якщо `.env` ще немає, створи його з прикладу:

```bash
cp .env.example .env
```

Запусти PostgreSQL та застосунок:

```bash
docker compose up -d --build --wait
```

API: http://localhost:8000, документація: http://localhost:8000/docs.
Код монтується з поточного каталогу в `/app` лише для читання й не копіюється
в образ. При кожному старті контейнера встановлюються залежності командою
`pip install -r requirements.txt` у `/opt/venv`, після чого виконуються
`alembic upgrade head` і запуск Uvicorn. Для встановлення залежностей потрібен
доступ до індексу Python-пакетів. Міграції при старті розраховані на один екземпляр API.

Після змін коду або requirements перезапусти API; перебудова образу не потрібна:

```bash
docker compose restart app
```

Усі сервіси підключені до спільної мережі `shortener` у межах Compose-проєкту.
Застосунок використовує адресу БД `url_db:5432`, k6 — адресу API `app:8000`.
Ці внутрішні адреси не залежать від `POSTGRES_HOST` і `POSTGRES_PORT` у `.env`.
`BASE_HOST` визначає публічну адресу коротких посилань;
`CACHE_SIZE` має бути додатним числом.

Дані PostgreSQL зберігаються в наявному каталозі `./pg_dump`.

## Навантажувальний тест

k6 використовує образ `grafana/k6` і запускається окремо:

```bash
docker compose run --rm k6
```

За замовчуванням тест працює 30 секунд із 10 віртуальними користувачами.
Кожна ітерація створює коротке посилання та перевіряє код редиректу й `Location`.
Переходи на зовнішні адреси вимкнені. Тест створює записи в налаштованій БД.

Змінити навантаження:

```bash
docker compose run --rm -e K6_VUS=50 -e K6_DURATION=1m k6
```

Сценарії розташовані в `k6/` і монтуються в контейнер лише для читання.
Переглянути логи та зупинити сервіси:

```bash
docker compose logs -f app
docker compose down
```
